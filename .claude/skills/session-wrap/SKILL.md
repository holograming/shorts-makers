# 세션 정리 (session-wrap)

**레포 기록이 정본이고, 메모리는 캐시다.** 메모리 파일, 스크래치, 압축 전 대화는 사라져도 된다. 다음 세션은 `docs/sessions/` 만 읽고 이어 간다. 세션마다 시작 → 일 → 정리 → (다음 세션이) 읽기를 반복하며 기록이 쌓인다.

## 자리

```
docs/sessions/
├── README.md        # 지금 상태 · 다음 할 일(정본) · 세션 목록(추가만)
├── patterns.md      # 반복되는 일 · 실수 · 사용자 교정의 누적표
└── YYYY-MM-DD-<slug>.md   # 세션 한 번의 회고 + 인계 (TEMPLATE.md 형식)
```
처음 쓰는 레포면 세 파일을 만들고, 진입점(AGENTS.md 표)에 `docs/sessions/README.md` 포인터 한 줄을 넣는다.

## 시작할 때 (읽기)
1. `docs/sessions/README.md` 의 "다음 할 일"과 가장 최근 세션 파일의 "인계"를 읽는다.
2. 메모리와 레포 기록이 다르면 **레포가 맞다.** 그 메모리는 고치거나 지운다.

## 끝낼 때 (쓰기)
1. **모으기:** 이번 대화(압축됐으면 요약 + 대화 원문 jsonl 경로), 마지막 세션 기록 이후의 `git log`, `git status`, 이전 인계의 "다음 할 일".
2. **회고:** [TEMPLATE.md](TEMPLATE.md) 의 회고 칸을 사실로 채운다.
   - 사용자의 결정과 교정은 **원문 그대로** 인용한다. 해석을 섞지 않는다.
   - 잘못한 것도 숨기지 않는다. 예: 되돌린 일, 헛걸음, 다시 물은 것.
   - 이전 인계 중 이번에 하지 못한 것은 "넘어온 것"에 적는다.
3. **인계:** 다음 세션이 이것만 보고 시작할 수 있게 쓴다.
   - 상태, 다음 할 일(추천 순서), 사용자가 정할 것, 로컬에만 있는 파일(경로와 다시 만드는 법), 함정.
   - 로컬 전용 파일(영상, 스크래치)은 다시 만드는 명령까지 남긴다. 그래야 지워져도 된다.
4. **패턴 누적:** `patterns.md` 표에서 이번 세션에 또 나온 항목의 횟수를 올리고 세션 링크를 붙인다. 새 항목은 1로 넣는다.
   - 3회 이상인데 아직 스킬이나 규칙이 아니면 → **스킬(또는 규칙) 후보**로 사용자에게 묻는다(질문 도구, 추천 하나를 맨 앞에). 만들지는 사용자가 정한다.
5. **README 갱신:** "지금 상태 · 다음 할 일"을 새 인계로 바꾸고, 세션 목록에 한 줄을 추가한다.
6. **메모리 다시 만들기:** 메모리 폴더를 본다.
   - 레포 기록과 겹치거나 낡은 `project` 메모리는 지운다.
   - `user` · `feedback` 중 레포에 없는 것만 남긴다.
   - `MEMORY.md` 에 "세션 기록 정본: docs/sessions/README.md" 포인터 한 줄을 둔다.
7. **커밋 · 푸시:** 레포 커밋 규칙을 따른다. 다른 기기 · 클라우드 세션이 이어받으므로, 작업 브랜치에 푸시까지 한다. 기본 브랜치면 먼저 브랜치를 만든다.
8. **보고:** 사용자에게 다섯 줄 안으로 알린다. 회고 핵심 하나, 다음 할 일, 사용자가 정할 것, 스킬 후보(있으면).

## 지키는 것
- 세션 파일은 추가만 한다. 이미 쓴 세션 파일은 고치지 않는다. 틀린 것은 다음 세션 파일에서 바로잡는다.
- 레포의 다른 정본(결정 로그, 규칙, 편별 기록)에 있는 내용은 옮겨 쓰지 않고 링크한다.
- 비밀값, 토큰, 개인 연락처는 쓰지 않는다.
- 사용자가 정할 일을 에이전트가 정하지 않는다. "정할 것"으로 넘긴다.
